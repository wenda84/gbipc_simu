# GB28181 IPC 模拟工具 — 工程说明

> 版本：2026-09-20｜适用工程：gbipc_simu 工程根目录（build.bat 所在目录）
> 面向开发者 / 维护者：架构、重编译 pjsua2、PyInstaller 打包、排障经验、文件索引、关键决策。
> 终端用户的使用方法见工程根目录 `Readme.md`。

## 1. 架构概述

### 1.1 信令优先（signaling-only）架构

底层用**自编译**的 pjsua2（非官方预编译 wheel）。官方 wheel 编译时
`PJMEDIA_HAS_VIDEO=0`，收到视频 INVITE 会**硬编码回 488**，因此本工程自编译了
`PJMEDIA_HAS_VIDEO=1` 的版本，并采用「信令优先」架构：

- pjsua2 **只做 SIP 信令**，不创建媒体流 / 编解码器；
- 真实 SDP 由**业务层**注入（pjsua 允许 `application/sdp` 覆盖自动生成的 SDP）；
- 真实 **PS / RTP 媒体**由独立发送器 `PsStreamer`（`app/media/ps_streamer.py`）负责，
  支持 UDP 直发与 TCP(RFC4571) 封帧。

分层（`app/` 下四层）：`ui`（PySide6 界面）/ `core`（配置、设备状态机、MANSCDP、SDP）/
`sip`（pjsua2 适配层，全工程唯一 `import pjsua2` 处）/ `media`（PS→RTP 发送器）。

### 1.2 为什么必须自编译 pjsua2

| 项 | 官方 wheel | 本工程自编译 |
|---|---|---|
| `PJMEDIA_HAS_VIDEO` | `0` → 视频 INVITE 硬编码 `488` | `1` |
| 媒体创建 | 自动创建音视频通道 | `PJSUA_CALL_NO_MEDIA_DEFAULT=1` 默认不创建 |
| SDP | 自动生成 | 业务层 `application/sdp` 覆盖 |

pjsua2 原生模块用**模块级 `__getattr__` 惰性加载**，静态分析看不到 `_pjsua2.pyd`，
因此「`import pjsua2` 成功」不等于原生模块可用——必须访问 `pj.Endpoint()` 才算真正加载
（见 §3 打包后自检）。`.pyd` 由 MSYS2/UCRT64 编译，链接 `libwinpthread-1.dll`
（不在系统 PATH，打包时需显式塞入）。

## 3. 重编译与打包

### 3.1 重新编译 pjsua2

仅在需要修改 pjproject 源码或 `config_site.h` 时才需要执行。工程已封装为一键脚本：

```bash
# 重编译 libpjsua + 重链接 .pyd + 自动部署到 venv312
bash tools/build_param/build_pjsua_win.sh

# 源码未改动、仅需重链接时（快得多）
bash tools/build_param/build_pjsua_win.sh --link-only
```

脚本会自行处理便携 MSYS2 的挂载、`PATH`、临时目录等坑，**请勿手工调用 gcc/g++**。

**关于编译输出**：日志中 `pjsua2-test` 目标会出现 `undefined reference to 'speex_*'` 报错——
这是官方自带 demo 程序的链接问题，**与本工具无关**，脚本已忽略。只要结尾出现
`BUILD_OK` 与 `DEPLOY_OK` 即表示成功。

编译完成后务必复跑 `Readme.md` §3 的自测确认没有回归。

### 3.2 自编译相关的关键宏

（`tools/pjproject-2.15.1/pjlib/include/pj/config_site.h`）

| 宏 | 作用 |
|---|---|
| `PJMEDIA_HAS_VIDEO 1` | 启用视频，消除「视频 INVITE 硬编码 488」 |
| `PJSUA_HAS_VIDEO 1` | 启用 pjsua 层的视频支持 |
| `PJSUA_CALL_NO_MEDIA_DEFAULT 1` | **信令优先核心开关**，统一守护 4 处源码改动 |

4 处受该宏守护的改动（**另有第 5 处，见 §3.2.1**）：

1. `pjsua_call.c` `pjsua_call_setting_default` — 默认不创建音视频媒体通道；
2. `pjsua_call.c` `invite_session` — 任意状态容忍 `ENOMEDIA`（**解决 488 的关键**）；
3. `pjsua_media.c` — 媒体行全被 `sort_media` 打负分时不再直接 488；origin 地址族回退；
4. `pjsua_core.c` `pjsua_process_msg_data` — 允许业务层 `application/sdp` 覆盖自动 SDP（**SDP 注入的关键**）。

### 3.2.1 第 5 处守护改动（国标语音广播，UAC 侧必需）

| 位置 | 改动 |
|---|---|
| `pjsua_call.c` `pjsua_call_on_media_update()` 的 **失败分支**（原 5325 行处） | 命中 `PJMEDIA_SDPNEG_ENOMEDIA` 时直接 `goto on_return`，**跳过 415 拆链** |

**为何必需（UAS 路径无此问题、UAC 路径必踩）**：

同一函数内的原有 ENOMEDIA 容忍补丁位于**成功分支**（原 5408 行），而失败分支的拆链条件是

```c
if ((inv->state != PJSIP_INV_STATE_NULL && inv->state != PJSIP_INV_STATE_EARLY
     && inv->state != PJSIP_INV_STATE_CONFIRMED) || ...)
    call_disconnect(inv, PJSIP_SC_UNSUPPORTED_MEDIA_TYPE, &reason);   /* 415 */
```

- **UAS**（平台 INVITE → 设备应答）：媒体更新时状态为 `EARLY`，不满足拆链条件；
- **UAC**（设备出呼，语音广播拉流）：收到 `200 OK` 时状态为 **`CONNECTING`** → 条件成立 → 被 415 拆链。

现象为：广播 INVITE 发出、平台回 200 OK 后呼叫立即 `DISCONNECTED 415 SDP negotiation failed`。
日志中仍会出现一条 `SDP negotiation has failed: ... ENOMEDIA`，属**预期噪声**。

**验证**：重编后广播链路稳定进入 `CONFIRMED`；`tests/selftest_full.py`（点播 TCP/UDP）、
`tests/gui_selftest.py`（10 项）、`tests/repro_midcall_stop.py` 全部无回归。
详见 `docs/GB28181_国标广播功能设计.md` §10.1。

### 3.3 打包为可执行文件（exe）

用 PyInstaller 打成**目录版**（exe + `_internal` 依赖目录），而非单文件：

```bash
cd 到工程根目录（即含 build.bat 的仓库根目录）
set MODE=onedir
runtime/venv312/Scripts/python.exe -m PyInstaller tools/build_param/build_exe.spec --noconfirm
```

产物结构（整体约 175 MB，可直接拷贝到别的 Windows 10/11 机器运行）：

```
dist/GB28181_IPC模拟工具/
├── GB28181_IPC模拟工具.exe     # 启动器（约 2 MB）
├── config/app_config.toml      # 配置（exe 同级，便携，可持久化）
├── Readme.md                    # 用户手册（exe 同级，直接查阅）
├── resource/ps_samples/*.ps    # PS 流素材（exe 同级，可直接增删替换）
└── _internal/                  # Python、Qt、pjsua2、图标等程序自身依赖
```

> **exe 同级目录中的 `config/`、`docs/`、`resource/ps_samples/` 由 `build.bat`
> Stage 4 负责拷贝**（PyInstaller 的 `datas` 只能落到 `_internal/` 内，详见 §6 打包坑）。
> 这样用户可替换素材、查阅手册，均无需重新打包；`_internal/` 则保持整洁。

**为什么不用单文件（onefile）**：单文件每次启动都要把约 75 MB 解压到临时目录，
实测**首次窗口弹出要 40 秒以上**（且易被杀毒软件实时扫描拖慢）；目录版约 3 秒即可。
单文件版仍可用 `set MODE=onefile` 构建，但不推荐日常使用。

**一键构建**：上述两段（编译 pjsua2 + 安装依赖 + 打包）已封装为工程根目录下的
`build.bat`，在 Windows 上双击或 `cmd` 中运行即可：

```bat
build.bat                :: 自动: 已部署 pjsua2 则跳过编译, 否则完整编译; 然后打包
build.bat --rebuild      :: 强制完整重编 pjsua2
build.bat --skip-build   :: 跳过编译(已部署 .pyd 时), 直接打包
build.bat --verify       :: 打包后启动 exe 做一次窗口冒烟验证
build.bat --onefile      :: 打包为单文件(不推荐, 见上)
```

> 该 bat 为 **GBK 编码 + CRLF 行尾**（中文 Windows 的 cmd 原生要求），
> 工程根目录由脚本自身位置（工程根目录）自动推导，可整体搬迁。
> 完整重编 pjsua2 约需数分钟（依赖便携 MSYS2），纯打包约 1 分钟。

打包时的四个关键点（已固化在 `tools/build_param/build_exe.spec`，改动前请先读）：

| 问题 | 处理 |
|---|---|
| `pjsua2` 用模块级 `__getattr__` 惰性加载，静态分析看不到 `_pjsua2.pyd` | `hiddenimports` 显式声明 `pjsua2._pjsua2` / `pjsua2.pjsua2` |
| `.pyd` 由 MSYS2/UCRT64 编译，链接 `libwinpthread-1.dll` 且不在 PATH | `binaries` 显式塞入该 dll |
| `AppConfig.ps_file` 是相对路径，打包后需定位到可替换的素材目录 | `AppConfig.ps_file_abs()` 按 **`USER_BASE_DIR`**（源码态=工程根，打包态=**exe 同级目录**）解析。**注意**：PyInstaller 的 `datas` 目标一律落在 `_internal/` 之下，目标名含 `.` 也**不会**提升到 exe 同级（已实测），故 PS 素材与用户手册**不放 `datas`**，改由 `build.bat` Stage 4 拷到 **exe 同级**的 `resource\ps_samples\` 与 `docs\`，用户可直接替换素材、查阅手册，均无需重打包 |
| 应用图标需同时作用于 **exe 文件**（桌面/资源管理器/任务栏固定）与**运行窗口**（标题栏/任务栏运行按钮） | `build_exe.spec` 的 `icon=` 设 exe 图标；`app/__main__.py` 用 `QApplication.setWindowIcon` 设窗口图标；`ipc.ico`/`ipc.png` 经 `datas` 打进 `resource/ui/` 随包发布（`app/core/app_icon.py` 按 `<ROOT_DIR>/resource/ui/ipc.ico` 解析，源码态/打包态通用） |
| **`sys._MEIPASS` 是临时/只读区，配置存进去重启即失效** | `config.py` 在 `sys.frozen` 时把配置目录改为 **exe 同级目录** `config/app_config.toml`（TOML 格式，可加 `#` 注释、按分组组织；旧版 `.json` 会在首次加载时自动迁移） |
| 位置一改，此前用源码版保存的配置「看起来丢了」 | 打包版首次启动且新位置为空时，`load_config()` 会**向上逐级查找并自动导入**旧位置配置，并在日志页提示来源；拷贝到别的机器上不会命中，无副作用 |

因此**配置文件随 exe 走**：`dist/GB28181_IPC模拟工具/config/app_config.toml`，
首次保存时自动生成；整个目录一起拷贝即为便携部署。

## 4. 排障经验（避免重复踩坑）

这两条是本工程实际排障中代价最大的认知偏差，记录备查：

1. **不要把 `PJSIP_EBUSY` 日志等同于「报文没发出去」。**
   `pjsua_acc_del()` 内部会重复调用一次注销并在 `status != PJ_SUCCESS` 分支打印该日志，
   但**注销事务其实已发出**。判断「是否发出」必须看**收包侧证据**（抓包或测试夹具的 inbox），
   而不是看 pjsua 自身日志。

2. **注销的 `401` 挑战必须在设备存活期间应答。**
   `pjsua_acc_del()` 会立刻 `destroy_regc(acc, PJ_TRUE)`（`force=TRUE` 绕过 `has_tsx` 保护），
   销毁注册上下文后 `401` 将无人应答，注销永远无法完成鉴权。
   本工程已通过 `wait_unregister_done()` 等待事务真正结束后再销毁账号来解决。

更多细节（完整根因链与验证证据）见
`_docs/handoff/gb28181-pjsua-siponly-20260920-2245.md`。

## 5. 已做关键决策

- **onedir 优于 onefile**：用户要求配置持久化；onefile 解压+杀软扫描约 40s 卡死，onedir 约 3s 弹出。
- **配置在打包态落 exe 同级**：且首次启动自动迁移旧工程根配置（解决「重启配置丢失」）。
- **Qt 跨线程 UI 复位必须用 `Signal`**，不能用 `QTimer.singleShot`（线程无事件循环不执行）。
- **`build.bat` 必须 GBK/CRLF**：括号内 `(` `)` 与 `&` 会破坏 cmd 解析（已规避：移除括号文案、`^&` 转义）。
- **`build_pjsua_win.sh` 不写死 `PROJ` 绝对路径**：改为可移植推导。

## 6. 批处理 / 打包环境坑（可复用）

- **`build.bat` 编码三连坑（关键，已固化）**：
  1. 必须 **GBK 编码 + CRLF 行尾 + 无 BOM**。UTF-8/LF 在 GBK 代码页下中文乱码、续行符失效；
  2. 括号块内 `echo` 的 `(` `)` 会被当成代码块分隔符 → 文案里的括号一律改掉或 `^` 转义；
  3. `echo` 里的 `&` 要 `^&` 转义。
- **PowerShell 工具不回传 stdout**：`.bat` 经 PowerShell `&` 运行无输出，结果需写文件再用 Read 读。
- **安全删除保护**：`rm -rf` 删除 >50 文件的目录会被沙箱拦截（PyInstaller 重建旧 dist 时也如此），
  改用**不存在的新输出目录**规避；清理大目录时用小批次 + 重试。
- **spec 路径推导**：`SPECPATH` 是 spec 所在目录，工程根要用 `dirname(SPECPATH)`（spec 已迁 `tools/build_param/`）。
- **`_MEIPASS` 是临时/只读区**：打包态配置必须改到 exe 同级目录，否则重启失效。
- **PyInstaller `datas` 落点（易误判，已实测）**：`datas` 目标**一律**落在
  `contents_directory`（默认 `_internal`）之下 —— 源码为
  `dest_path = os.path.join(COLLECT.name, COLLECT.contents_directory or "", dest_name)`。
  目标名**含 `.` 也不会**被提升到 exe 同级（那是 `shutil.copytree` 的约定，PyInstaller 不适用）。
  实测：`datas=[(f,'resource.ps_samples')]` → `_internal/resource.ps_samples/`。
  **若需资源落在 exe 同级**，两条路：
  (a) 由 `build.bat` 打包后拷贝（本工程采用，保留 `_internal` 整洁）；
  (b) `EXE(..., contents_directory='.')` 禁用 `_internal`，但会把 150+ DLL/PYD 平铺到 exe 同级。
  图标等程序自身资源放 `datas` 即可（在 `_internal` 内由 `app_icon.py` 解析）。
- **便携 MSYS2 的 bash 完全不继承外部环境变量**（连 `export` 的也不继承）：
  `PROJ_ROOT=xxx tools/msys64/usr/bin/bash.exe -c '...'` 在子进程里读到的是**空值**，
  会让 `build_pjsua_win.sh` 把工程根解析成 `/`（报 `cd: /tools/pjproject-2.15.1/...` 不存在）。
  正确调用方式是**把脚本路径作为参数传进去**，由脚本自身按 `$0` 推导工程根
  （`build.bat` 就是这么做的）：
  ```bash
  tools/msys64/usr/bin/bash.exe --norc --noprofile "D:/.../tools/build_param/build_pjsua_win.sh"
  ```
- **`QToolBar.addWidget()` 的控件可见性由 `QWidgetAction` 托管**：对控件本身
  `setVisible(False/True)` **无效**（工具栏布局会把它显示回去），必须保存
  `addWidget()` 返回的 `QAction` 并用 `action.setVisible()` 控制。
  （国标广播的「音量提示框」按勾选显隐即踩过此坑。）

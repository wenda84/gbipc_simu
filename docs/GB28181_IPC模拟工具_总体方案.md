# GB28181 IPC 模拟测试工具 — 总体方案

> 版本：v1.0（规划稿）  
> 依据：GB/T 28181-2016（docs/ 下原文 PDF）、pcap/ 实测抓包（海康 IPC ↔ 178 平台）、独立工具 ps_sender 既有工程（已并入本工程 `app/media/ps_streamer.py`，原工具已删除）

---

## 1. 需求理解

实现一个运行在 **Windows** 上的国标 IPC（前端 SIP 设备）模拟测试工具，角色为 **UAS/UAC 一体的 SIP 设备**：

1. **注册**：向 SIP 服务器（平台）注册，支持数字摘要认证（401 挑战应答）、刷新注册、注销。
2. **响应呼叫**：接收平台 INVITE（实时点播，`s=Play`），按国标回复 100/200(SDP)，ACK 后向平台推送媒体流，收到 BYE 停止。
3. 上述两功能依赖的辅助接口按国标一并实现：**周期心跳（Keepalive）**、**设备信息/状态/目录查询应答**（注册后平台必然下发）。
4. 媒体发送复用并改造独立工具 ps_sender → 现为 `app/media/ps_streamer.py`（PS over RTP）。
5. 提供基础设置页面（参考海康"平台接入"截图，裁剪出我们需要的参数）。
6. **PJSIP 作为底层协议栈**，与业务代码分层隔离。

## 2. 国标流程梳理（结合抓包实证）

### 2.1 注册 / 刷新 / 注销（标准 9.1）

```
IPC → REGISTER（无鉴权, Expires: 3600）
IPC ← 401 Unauthorized（WWW-Authenticate: Digest realm=..., nonce=..., qop="auth,auth-int"）
IPC → REGISTER（Authorization: Digest username=..., response=MD5(...), qop=auth, nc=00000001）
IPC ← 200 OK（Contact;expires=3600, Date 授时）
```

要点（9.1.1）：
- 注册过期时间可配置，**缺省 86400s，不得短于 3600s**；到期前须**刷新注册**（流程同首次注册）。
- 注册失败须间隔重试，间隔可调，**一般不短于 60s**。
- 注销 = REGISTER 且 `Expires: 0`（同样走 401 挑战应答）。
- 抓包实证：`REGISTER sip:34020100002000000178@172.220.0.178:5080`，From/To 为设备 20 位 ID@平台域，Contact 为 `sip:设备ID@本机IP:5060`；服务器 401 中 qop="auth,auth-int"，设备以 qop=auth 应答（MD5）。
- 校时（9.10）：200 OK 的 `Date` 头域授时，设备应接受（实现上记录即可）。

### 2.2 心跳 / 状态信息报送（9.6，MANSCDP A.2.5）

- IPC 注册成功后按"心跳间隔"（**默认 60s**）周期发送 `MESSAGE`，体为 MANSCDP XML：
  ```xml
  <?xml version="1.0" encoding="GB2312"?>
  <Notify><CmdType>Keepalive</CmdType><SN>递增</SN>
  <DeviceID>设备20位ID</DeviceID><Status>OK</Status></Notify>
  ```
- 平台回 200 OK（无消息体）。连续超时达"心跳超时次数"（**默认 3**）认为对方离线 → 触发重新注册。
- Content-Type: `Application/MANSCDP+xml`。

### 2.3 查询应答（9.5，注册后平台必然下发，属依赖项）

平台经 `MESSAGE` 下发 `<Query>`，IPC 须先回 **200 OK（无体）**，再单独发 `MESSAGE` 携带 `<Response>`：

| 查询 CmdType | 应答要点（A.2.6） |
|---|---|
| DeviceInfo | Result、DeviceName、Manufacturer、Model、Firmware、Channel |
| DeviceStatus | Result、Online(ONLINE)、Status(OK)、Encode、Record、DeviceTime |
| Catalog | SumNum、DeviceList Num、Item（DeviceID/Name/Manufacturer/Model/CivilCode/ParentID/Status=ON…），支持附录 N 多响应 |

抓包实证：平台注册成功即向 IPC 下发 `DeviceInfo` 查询；海康回 `encoding="GB2312"` 的 Response。Catalog 的 Item 字段与附录 O 示例一致。

### 2.4 实时点播应答（9.2，UAS 侧视角）

```
平台 → INVITE（Subject: 发送者ID:序列号,接收者ID:序列号；SDP: s=Play, m=video <port> TCP/RTP/AVP 96,
              a=setup:passive, a=connection:new, a=recvonly, a=rtpmap:96 PS/90000, y=0000000062, f=v/////a///）
IPC  → 100 Trying
IPC  → 200 OK（SDP: s=Play, c=IN IP4 <本机IP>, m=video <本机媒体端口> TCP/RTP/AVP 96,
              a=setup:active, a=sendonly, a=rtpmap:96 PS/90000, y=<与Offer一致>）
平台 → ACK
IPC  → 推送 PS/RTP 媒体流
平台 → BYE → IPC 200 OK → 停止推流
```

要点：
- **Subject 头域**（附录 K）：`媒体流发送者ID:发送方流序列号,接收者ID:接收方序列号`，点播必须支持。
- **y 字段（SSRC）**：10 位十进制，点播域内设备时由平台在 Offer 中指定，**设备 200 OK 原样带回并用作 RTP SSRC**（抓包实证：y=0000000062，RTP SSRC=62；另一抓包 y=0000000001，SSRC=1）。
- **f 字段**（附录 F）：媒体参数 `f=v/编码/分辨率/帧率/码率类型/码率a/编码/码率/采样率`；平台 Offer 常见 `f=v/////a///`（空参数占位），设备侧可不回或按需回。
- SDP 必备行（附录 F）：v/o/s/c/t/m/a/y（o 的 username = 设备编码；t=0 0 表示实时）。
- 方向属性：平台 recvonly ↔ 设备 sendonly。
- 错误码：无法满足 SDP → 488；呼叫能力不足 → 486。
- 媒体保活（附录 M）：收不到对端信令/链路异常时停止发送；同一 Subject 媒体源重复呼叫时释放旧链路建新链路。

### 2.5 媒体传输（附录 C / F / L）

- **封装**：PS 流（ISO/IEC13818-1）整体作为 RTP 负载；**PT=96，时钟 90kHz，m 行 media=video，rtpmap:96 PS/90000**（附录 C.1）。
- **UDP**：`m=video <port> RTP/AVP 96`，RTP 分片直接发。
- **TCP**（附录 L）：`m=video <port> TCP/RTP/AVP 96`，**RFC 4571 封帧 = 2 字节大端长度前缀 + RTP 包**；通过 `a=setup:active/passive` 协商 TCP 主/被动；平台 Offer 给 `setup:passive` 时，**设备作为 TCP 客户端主动连接**平台媒体地址（抓包实证：`05 84` = 1412 = 12 字节 RTP 头 + 1400 负载，逐帧验证通过）。
- **字符集（6.10）**：信令宜 GB2312；抓包中海康 Query/Response 用 `encoding="GB2312"`，平台用 GBK。实现上 MANSCDP 消息体统一按 GBK 编码（GBK 兼容 GB2312），解析按 GBK 容错。

## 5. 总体架构

### 5.1 分层设计（PJSIP 与业务隔离）

```
┌─────────────────────────────────────────────────┐
│ UI 层 (PySide6)                                  │
│  MainWindow: 平台接入配置页 / 状态页 / 信令日志页  │
├─────────────────────────────────────────────────┤
│ 业务层 core/                                     │
│  GbDevice      注册/心跳/重试 状态机              │
│  GbCallManager INVITE 应答、推流调度、BYE 处理     │
│  Manscdp       XML 构造/解析 (GBK)               │
│  GbSdp         Offer 解析 / Answer 构造          │
│  AppConfig     配置模型 + JSON 持久化            │
├─────────────────────────────────────────────────┤
│ 协议适配层 sip/  ←—— 唯一 import pjsua2 的地方     │
│  SipStack(抽象接口)                               │
│  └─ PjsipStack: Endpoint/Account/Buddy 封装      │
│     回调 → 中性事件对象(sip_events.py) 上报业务层  │
├─────────────────────────────────────────────────┤
│ 媒体层 media/                                    │
│  PsStreamer (app/media/ps_streamer.py): UDP/TCP   │
│  start(dest, ssrc, pt, proto) / stop()           │
└─────────────────────────────────────────────────┘
```

**隔离规则**：业务层只依赖 `sip/` 暴露的抽象接口与中性事件对象（纯 dataclass，不含任何 pjsua2 类型）；pjsua2 仅在 `sip/pjsip_stack.py` 出现。后续若替换协议栈，业务层零改动。

### 5.2 线程模型

- pjsua2 回调运行在 PJSIP 工作线程 → 回调内只做**解析+投递队列**，立即返回；
- 业务层事件循环（单线程 worker）消费队列：状态机、发 MESSAGE、控制推流；
- UI 经 Qt 信号槽接收业务层通知（不直接碰 sip 层）；
- 媒体发送独立线程（沿用 ps_sender 原有 pacing 逻辑，未改动）。

### 5.3 PJSIP 关键实现点（API 已逐一验证）

| 需求 | pjsua2 机制 | 验证结果 |
|---|---|---|
| 注册+摘要认证 | `AccountConfig.regConfig`(registrarUri, timeoutSec, retryIntervalSec) + `AuthCredInfo(username, realm="*", data=密码)`，401 由协议栈自动处理 | 字段齐全 ✅ |
| 注册状态/刷新/重试 | `Account.onRegState`；timeoutSec=注册有效期；协议栈自动刷新 | ✅ |
| 发带外 MESSAGE（Keepalive/Response） | 以平台 URI 建 `Buddy`，`Buddy.sendInstantMessage(param)`，param.contentType=`Application/MANSCDP+xml` | 存在 ✅ |
| 收 MESSAGE | `Account.onInstantMessage` → OnInstantMessageParam.msgBody/contentType/rdata | 字段齐全 ✅ |
| 收 INVITE | `Account.onIncomingCall` → rdata.wholeMsg 取原始报文解析 SDP Offer | ✅ |
| 自定义 200 OK SDP | `Call.answer(CallOpParam)`：`opt.audioCount=0/videoCount=0`（关闭 PJSIP 自带媒体），`txOption.contentType="application/sdp"` + `txOption.msgBody=我方SDP全文` | 字段齐全 ✅（运行时需首验 body 覆盖生效；备选 `Call.onCallSdpCreated` 改结构体） |
| BYE / 挂断 | `Call.onCallState` → DISCONNECTED 停推流 | ✅ |

**SDP Answer 模板**（TCP 模式，UDP 模式替换 m 行与 setup 属性）：

```
v=0
o=<设备ID> 0 0 IN IP4 <本机IP>
s=Play
c=IN IP4 <本机IP>
t=0 0
m=video <本机媒体端口> TCP/RTP/AVP 96
a=setup:active
a=sendonly
a=rtpmap:96 PS/90000
y=<Offer中的y原样带回>
```

### 5.4 ps_sender 改造点（成果即现 `app/media/ps_streamer.py`）

1. `RTPStreamer` 构造参数化：`dest_ip/dest_port/payload_type(96)/ssrc(=协商y值)/protocol(udp|tcp)`；
2. 新增 **TcpRfc4571Streamer**：先按 SDP 协商作为 active 方 TCP 连接平台 `c/m` 地址，发送时每帧前加 2 字节大端长度前缀；
3. 删除未使用的模块级 `DEST_IP/DEST_PORT/SSRC` 常量，改为调用方注入（保留 CLI 用法兼容）；
4. 封装 `start()/stop()` 供业务层调用，发送统计（包数/字节/码率）回调上报 UI。
